> 校验状态：本文**未运行** `npm run typecheck` / `npm test` / `npm run build`（按分工由脚本最后统一跑）；所有结论都是源码级证据，唯一实测过的仓库外事实在笔记里已标注。

## 一、目标与原则

1. **引导就是引导**：跟练只演示「这条链怎么走通」。删除结束卡的「真跑一次 / 存成我的工作流模板 / 留在画布上继续做」，也不做「帮我…」「我要改」两条人工介入路径；退出只有一个动作：还原并离开。
2. **全程只读**：跟练开始后画布对用户只读（节点不可拖 / 不可连 / 不可删 / 不可写参数 / 不可提交），只保留读操作（选中查看、平移缩放、退出还原）。写入只允许两路：跟练自己的 `prepare`、被回放接管的生成。**Inspector 全程紧凑态**：不再强制展开成大面板盖住画布（现状 `useCanvasPracticeHost.ts:498-507`），提示词/模型/参数一律 `readonly`。见 §四。
3. **从易到难**：入门一条「图片 + 视频」最小骨架；进阶按创作方向（角色 / 场景 / 分镜）；高阶做交付规格、镜头语言与口播音频。每条剧本的**图形态必须真的不同**（§二表），不是换文案。
4. **动效有质感**：相机补间、聚光跟手、卡片/清单/步骤/药丸/角标都有明确时长与缓动；有全局 `prefers-reduced-motion` 降级。见 §六。
5. **零消耗**：不提交任何模型任务；回放产物是仓库自带示例素材（`public/images/tutorial/frame.jpg`、`clip.mp4`，新增 `voice.mp3`）。跟练期间的「生成」一律被 `replaySubmit` 接住，见 `useCanvasPractice.ts:143-188`。
6. **能力缺口如实说**：平台没有的能力（BGM/音效生成、单节点 multi_prompt、独立分镜/角色/场景节点形态、画布内合成、音频语种/音色持久化）写进课程文案与 §十一，不用假演示糊过去。

**做不到的方向，为什么不做到，平台缺什么**（写进交付报告，也写进对应课程的正文）：

- **音效 / BGM 生成**：平台没有文生音乐 / 音效库，只有「用户自备音频资产」与「从视频分离 / 提取」（`canvas-workflow-presets.ts:125` 明确「允许清单里没有 TTS 模型」；`canvas-media-job.ts:53` 只有 `bgm_separation`）。所以 `talking-and-audio` 教的是**音频节点承载旁白/配乐 + 口播原生出声**，并在正文写明「生成音效平台还没有」。
- **单节点 multi_prompt（一条视频节点吃多条分镜提示词）**：前端与后端契约都是单值 `prompt`（笔记 02 §三，全仓 grep 零命中）。多镜头只能多节点 + 合成，课程按这个口径教。
- **独立形态的「分镜 / 角色 / 场景节点」**：不存在；角色 / 场景是主体库的两种 `kind`，分镜靠多节点与分镜组（`app/utils/canvas-group.ts:13-24`）。
- **3D 导演台预演 → 出片（负责人第 6 条）**：能力大多在（three.js 导演台、机位关键帧求值 `app/utils/director/camera-path.ts:133`、机位截图 `capture-shot.ts:7`、运镜视频导出 `video-export.ts:124`），缺的是「按时间轴精确导出帧序列」与「白模/深度 pass」两块基建（`app/` 内 renderTarget / MeshDepthMaterial 零命中）。**本轮不做这条课**：它依赖 `docs/3D场景预演与新管线调研.md` §五 阶段一的导出器（`planPreviewFrames` / `exportPreviewFrames`），且单 `url` 的 `PracticeReplay` 结构（`canvas-practice.ts:22-32`）要扩多产物——属于另一件事。待阶段一落地后，它是本套引擎的下一条高阶剧本（形态：`image×2 → video×2` 的预演帧序列），不需要新引擎。
- **Codex 类编程智能体 + Blender 生成场景**：按 3D 调研 §七 的结论定位为长期/企业版方向（整场场景成功率外部实测为 0%，且仓库是纯前端 + 冻结后端，没有跑 Blender 的位置），本轮不做；产品侧先做「可插拔控制通道」的接缝（阶段一）。
- **合成 compose / 一稿多版 / 蒙太奇 / 媒体动作（高清 / 补帧 / 逐帧拉片 / 分离音频）**：能力在，但都要求真实 `assetId` 或入口在成片工作室（`app/utils/canvas-matrix.ts:144-152`、`canvas-montage.ts:76-80`），回放产物的 `assetId` 恒为 `undefined`（`canvas-practice.ts:379-380`），进不了零消耗沙盒。课程里只作为「观念 + 后续入口」写进正文。

## 三、每条剧本的逐步规格

### 3.0 共同约定（四条机制，一套吃七条剧本）

**判据 `gate`（只读 view + 会话进度，不再要求用户手写）**：

| gate | 满足条件 |
| --- | --- |
| `{ kind:'node', nodeKind, atLeast, key? }` | 作用域内该 `kind`（带 `key` 时该 key 的节点）数量 ≥ atLeast |
| `{ kind:'edge', fromKind, toKind, fromKey?, toKey? }` | 两节点之间存在边 |
| `{ kind:'prompt', nodeKind, key? }` | 该节点 `prompt` 或 `content` 非空（文本节点用 `content`）。**前置改动（必须做，否则文本类判据永不满足）**：`practiceGraphView` 现在写的是 `String(node.data?.prompt ?? node.data?.content ?? '')`（`canvas-practice.ts:143`），而 `addNode` 建节点时写死 `prompt: ''`（`useCanvasAddNode.ts:57-62`）——空串不是 nullish，`??` 不会回落到 `content`，文本节点视图的 `prompt` 恒为空串。W1 必须把这一行改成 `String(node.data?.prompt \|\| node.data?.content \|\| '')`（即 `prompt` 为空串时回落到 `content`），并补一条单测（节点 data 同时有 `prompt:''` 与 `content:'x'` 时视图 `prompt === 'x'`） |
| `{ kind:'model', nodeKind, model, key? }` | 该节点 `model` 等于声明值 |
| `{ kind:'subject', nodeKind, key?, atLeast? }` | 该节点 `subjectIds` 数量 ≥ atLeast（默认 1） |
| `{ kind:'talking', nodeKind, key? }` | 该节点 `data.talking.script` 非空 |
| `{ kind:'result', nodeKind, key?, atLeast? }` | 该节点（或该 kind 的节点数）已有回放产物 |
| `{ kind:'demo' }` | **引导自己演示之后算完成**：宿主在「备好 + 定位 + 停一拍」之后把 `step.id` 写进 `session.done`，`practiceStepSatisfied` 读它 |

`practiceStepSatisfied(step, view, doneIds?)` 是完成态的唯一入口（Tour 的 `satisfied`、清单打勾、主按钮禁用都用它），判定 = **`gateSatisfied(step.gate, view)` 或 `doneIds.has(step.id)`**；`gateSatisfied` 保持 view-only 不动（自动备好计划仍只看它）。`doneIds` 有两条写入路径：① `demo` 步由宿主在演示后写入（纯讲解步，不产节点、不产产物、步内没有用户动作）；② **任何 `result` 步都允许「跳过这一步」**（卡片底栏次按钮，回放在飞时禁用），写入同一个 `session.done` —— 这是所有「点生成」步的统一逃生口，避免任何平台前提（例如清单里没有带原生出声的模型）把人锁死在一步里；跳过的步照样打勾（进度只增不减），但不写产物。

**自动备好 `prepare`（6 种，执行侧全部走 `updateNodeData`，退出随快照还原）。共同语义（六条剧本都靠它跑通，缺一条就整条链建不出来）**：

1. **定位**：先按 `key` 在跟练作用域内找 `data.practiceKey === key` 的节点；无 `key` 时找该 `kind` 的第一个节点。
2. **缺则新建**：找不到就**按 `nodeKind` 新建**（落点：有 `fromKey` 时 = 上游节点右侧 80px，否则 `practiceSpotForNewNode`，画布空时视口中心），**并在同一拍 `updateNodeData` 写 `practiceKey = key`**——`add-node`/`add-connect`/`add-text`/`image-setup`/`video-setup`/`audio-setup` **六种一律如此**（现状 `practicePrepareAction` 是「找不到就 `fail()` 早退」，见 `useCanvasPracticeHost.ts:366-370`，必须改掉）。
3. **补边**：凡带 `fromKey`（或 `add-connect` 的 `fromKind/toKind`）的，缺边就 `linkNodes({ source, target, sourceHandle:'out', targetHandle:'in' })`。
4. **字段一律写**（画布只读，不存在「用户已写过的字」需要让位；`fillEmptyOnly` 那套旗标随之删除）。
5. **`model: 'auto'`**：只在 `video-setup` 用，表示由宿主调用注入的 `resolveTalkingModel()` 现场解析「清单里带原生出声能力的视频模型」；解析不到就不写 `videoMode:'talking'`（保持 `i2v`）、照样写 `data.talking`，并置 `session.notice`（见 §3.5）。

| prepare | 参数 | 写入 |
| --- | --- | --- |
| `add-node` | `nodeKind, key?, label?` | 建节点 + 标 `practiceKey`（无其余字段） |
| `add-connect` | `fromKind, toKind, fromKey?, toKey?, key?` | 缺节点就建（落 from 右侧 80px，与 `graphOriginPoint` 同口径），再连线 |
| `add-text` | `content, key?` | 缺文本节点则建，并写 `content` |
| `image-setup` | `nodeKind` = 'image' 或 'panorama'（其余字段：`key?, fromKey?, model, params, prompt?, subjectKind?`） | 缺则建；写 `model/params/prompt`；`fromKey` 补边；`subjectKind` 解析并写 `subjectIds/subjectVersions` |
| `video-setup` | `nodeKind` 固定 'video'；`key?, fromKey?, textUpstream?:{key,content}, model`（'auto' 或具体模型 id）, `videoMode, params, prompt?, subjectKind?, talking?, camera?` | 缺则建；写 `model/params/prompt/videoMode`；`textUpstream` 缺文本上游就建并连线；`talking` 走 `normalizeTalkingData` 并置 `videoMode='talking'`、默认时长 `talkingDuration(script,null)`；`camera` 写 `cameraMoves` + `params.fx` + `camera:{on:true,...}` |
| `audio-setup` | `nodeKind:'audio', key?, label?, prompt?, params:{duration}` | 缺则建；写参数与描述；**不写 model**（允许清单里没有 TTS 模型，写了会「模型未定价」，见 `canvas-workflow-presets.ts:125`） |

> 评审提到的「七条剧本里没有任何一步用 `add-node` 建 setup 节点」：本版按上面的第 2 条把建点语义**内建进四个 setup 与 `add-text`**（而不是给每条剧本补 `add-node` 步）——理由是 setup 与建点本就该同一拍完成（同一 tick 内 `practiceKey` 必须已落，否则下一次 `practiceScopeNode(key)` 找不到它），补成两步只会让「点了继续却没出现节点」的空窗更多。原先单列的 `subject` prepare 已删除：七条剧本里没有只用它的一步，主体引用统一由 `image-setup`/`video-setup` 的 `subjectKind` 承担，锚点仍是 `inspector-subject`。

**回放 `replay`**：`{ simulatedMs, url, failOnce?, byKey? }`。`byKey` 是「一 key 一份回放」——多镜/多规格剧本里一个步骤要对多个节点各演一次的必须用它；`practiceReplayFor(replay, nodeKind, nodeKey)` 解析并校验节点类型 ∈ `PRACTICE_REPLAY_KINDS = ['image','video','audio']`（**比现状扩了 audio**；文本节点不需要回放）。每条剧本**第一个出片回放**带 `failOnce:true`（失败演练：第一次演失败态，再点一次成功，全程零消耗），其余回放不带。

**产物预览 `showcase`**：`{ nodeKind:'video'|'audio'|'image', url, model, prompt, params? }`，只在收尾步配；宿主优先复用作用域内同类节点（内容为空或已是同一 url），否则视口中心新建，然后**相机补间**居中（`camera.glideTo`）。

**卡片文案规则**（修掉验收记录里「卡片写的不等于画布真实状态」那条）：「已为你准备好」那一行不再由剧本静态推导，而是由**宿主实际执行过的 prepare** 反推（`session.applied` → `practiceReadyItems(step, applied)`）。跟练没写进去的东西，卡片不上行；没写成功（例如主体库为空）写 `session.notice`，卡片上以提示行显示。

**卡片底栏三态**（没有「帮我…」「我要改」）：① `result` 判据未满足时，主按钮禁用并显示「等你动手：{gateHint}」（每个 `result` 步都必须写 `gateHint`，W1 测试强制）；② 满足后或非 `result` 步，主按钮为「继续」（收尾步为「完成，退出并还原画布」）；③ **只要有 `result` 判据，底栏就带一个次按钮「跳过这一步」**（回放在飞时禁用，点击写 `session.done`）。ready 区标题固定为「跟练已替你布好这一步」。

**正文模板**：每步 `body` = 固定开场句 + 本步要点（≤ 60 字）。固定开场句（3 条，全剧本共用）：开场步用「跟练不会真的调模型、不花点数；退出会把画布还原成进来那一刻。」；首次点生成那步用「回放放的是跟练自带的示例素材，不是按你这句提示词真生成的。」；其余步复用「跟练已经替你把这一步布好了，你只要点生成看回放。」要点句由 W1 与剧本一起写，W6 同步翻译。

**下表简写**：`{node,image,1}` = `{ kind:'node', nodeKind:'image', atLeast:1 }`；`{edge,image→video}` = `{ kind:'edge', fromKind:'image', toKind:'video' }`；`{subject,image,key:'cast-image'}` = `{ kind:'subject', nodeKind:'image', key:'cast-image' }`；`{talking,video,key:'talk'}` = `{ kind:'talking', nodeKind:'video', key:'talk' }`；prepare 列省略 `kind` 的写法同义（如 `{image-setup,image,key:'cast-image',…}` = `{ kind:'image-setup', nodeKind:'image', key:'cast-image', … }`）；回放列 `7000ms · frame.jpg` = `{ simulatedMs:7000, url:'/images/tutorial/frame.jpg' }`，`byKey：<key> …` = `{ byKey: { <key>: { … } } }`。锚点 `inspector-*` 一律在 Inspector **紧凑态**下定位（不展开面板）。`key` 缺省（如 `image-video-basics` 的全部 prepare）时按「作用域内该 kind 的第一个节点」定位。

## 六、交互动效规格

### 6.1 相机补间（W2）

新建 **`app/utils/canvas-viewport-tween.ts`**（纯函数、零依赖、node 环境可测）。**不叫 `canvas-camera.ts`**：该路径已被「摄影提示词库」占用（`app/utils/canvas-camera.ts:1-16` 的 `CameraSetup` 与 `cameras` 表），Nuxt4 `app/utils/**` 自动导入会撞名，故改名为与 `app/utils/canvas-viewport.ts` 并列的 `canvas-viewport-tween.ts`。

```ts
export type CanvasViewport3 = { x: number, y: number, zoom: number }
export const CAMERA_GLIDE_MIN_MS = 200
export const CAMERA_GLIDE_MAX_MS = 420
export const CAMERA_GLIDE_MS_PER_PX = 0.25
export function canvasEaseOutCubic(t: number): number
export function canvasViewportAt(from: CanvasViewport3, to: CanvasViewport3, t: number): CanvasViewport3
export function canvasTweenDuration(from: CanvasViewport3, to: CanvasViewport3, opts?: { minMs?: number, maxMs?: number, msPerPx?: number }): number  // 160 + 0.25*位移，夹 [200,420]
export function canvasViewportSettled(a: CanvasViewport3, b: CanvasViewport3): boolean  // dx|dy<0.5px 且 dzoom<0.001
export function canvasRevealShift(anchor: { left, top, right, bottom, height }, pane: { left, top, width, height }, pad?: number): { dx: number, dy: number }  // 现在 host:219-242 的几何搬出来
export function canvasApproachFactor(dtMs: number, halfLifeMs: number): number  // 1 - 2^(-dtMs/halfLife)；halfLife<=0 → 1
export function prefersReducedMotion(win?: { matchMedia?: (q: string) => { matches: boolean } }): boolean
```

默认时长 **`--st-motion-camera` = 260ms**（对 100–400px 位移由 `canvasTweenDuration` 给出 200–260ms），缓动 `easeOutCubic`；**只插值 x/y**（跟练的 reveal 与成片居中都恒等 zoom，`useCanvasPracticeHost.ts:243、453`）。`DESIGN.md:745` 的 150–200ms 是给 hover/focus 的，整屏级位移刻意取更长，评审时按这条口径。

**Driver `app/composables/useCanvasCameraGlide.ts`**：返回 `{ glideTo(to, {durationMs?}): Promise<boolean>, panBy(dx, dy, o?): Promise<boolean>, cancel(): void, tweening: Ref<boolean> }`。**命名统一**：宿主里实例名固定为 `camera`（`const camera = useCanvasCameraGlide({ viewport: opts.viewport, setViewport: opts.setViewport })`），宿主把它作为返回值成员 `camera` 暴露；Workspace 侧顶层别名 `const practiceCamera = practice.camera`（模板里不能写 `practice.camera.cancel()` 的链式取值——宿主返回的是普通对象，模板只拆顶层 ref；`tweening` 同理要落成 `const practiceCameraTweening = practice.camera.tweening`）。约束（写进实现注释）：

- **单一补间槽**：新目标覆盖旧目标，起点 = 旧补间的**当前插值**（自己持有 `current`，**不许每帧回读 `opts.viewport.value`**：selection 拖拽期间 `viewport.value` 会停止跟随 d3）。
- 一帧只写一次 `setViewport`；循环里禁止再调 `setCenter` / `fitView`。
- 不绑 `@viewport-change` / `@move`（每帧都触发，易成环）。
- 收敛即写最后一帧精确值（避免亚像素抖动）；`reducedMotion` 为真 → 直接写一次目标，不进 rAF。
- `session.active` 变 false / `onScopeDispose` → `cancel()` 且不写最后一帧。

**`revealPracticeAnchor` 的三处改动**（`useCanvasPracticeHost.ts:210-246`）：① 瞬移换 `camera.panBy(dx, dy)`；② 补间结束后再量一轮（原 `measure<1` 的 `nextTick` 放宽到 `<2`，吸收 240ms 对话栏折叠/面板重排造成的过期 pane）；③ **补间在飞时不再发起新的 reveal 重试**（等渲染的 rAF 重试必须 `!camera.tweening`），否则会拿移动中的元素矩形算 dx/dy。`ensurePracticeShowcase` 的 `setCenter`（`:453`）换 `camera.glideTo`。

### 6.2 聚光平滑（W3）

替换 `CanvasPracticeTour.vue:247-273` 的 400ms `setInterval`：一个常驻 rAF 循环（仅 `session.active` 期间），**分级节流**：锚点矩形 + 平滑 + 写 `spot` + 卡片选位 = 每帧；`collectZones()` 与 `measureList()` = 每 8 帧（≈7.5Hz）；`readCardSize()` = 仅切步 / ResizeObserver。

- 平滑用帧率无关指数趋近：`next = cur + (target - cur) * guideApproach(dt, halfLife)`，`guideApproach = 1 - 2^(-dt/halfLife)`。
- **稳态跟随 `halfLife = 90ms`**；**相机补间在飞时 `halfLife = 0`（直落）**——否则匀速移动的锚点会带来 ≈`v*hl/ln2` 的恒定滞后（300px/260ms 时 ≈150px，聚光框会明显吊在节点后面）。宿主把 driver 的 `tweening` 暴露成 `practice.camera.tweening`，W4 用顶层别名 `practiceCameraTweening` 传成 Tour 的 `cameraTweening` prop；`useGuideOverlay` 的 `directFall` 读它（W3 只认 prop，不认宿主）。
- **锚点身份切换（换步 / 换节点）直落**：比较 `practiceAnchorKey(step, view)`（W1 导出，= `step.id + '#' + anchorSelector(...)`），变了就 k=1。
- **`spot` 恒在**：删掉模板里的 `v-else` 遮罩分支与 `spot.value = null`；锚点消失 = 把矩形补到整视口 `{0,0,innerW,innerH}`（视觉上是洞收拢成全屏遮罩），锚点出现 = 从整视口收到节点框（**不要从 `{0,0,0,0}` 起**，会出现一条线扫过）。
- **卡片避让移位**同样平滑（`halfLife = 110ms`），滑行期间给卡片加 `.is-gliding { pointer-events: none }`（卡片是 `auto`，滑过锚点会吞掉用户一次点击）。
- **位置一律走 `transform: translate3d(x,y,0)`**，`left/top` 固定为 0：`.canvas-guide` 是 `position: fixed; inset: 0`（`canvas.css:747-753`），坐标原点即视口原点，数值等价。**两个坑**：① `cardStyle` 的兜底分支带的 `bottom:'28px'` 必须一起清掉；② `readCardSize` 的准入条件是 `cardEl.style.width` 非空（`CanvasPracticeTour.vue:201`），迁 transform 后**必须继续写 inline width**，否则卡片尺寸永远停在 340×250、选位几何整段静默失效。③ 选场景卡自己的 `transform: translate(-50%,-50%)`（`canvas.css:6516`）不参与这套定位。
- **禁止**给 `.canvas-guide__spot` 写 CSS `transition`（与 rAF 抢同一属性）。

**性能约束**：`spot` / `cardPos` / `listRect` 都是整对象替换，**数值没变就不写**（比较 4 个数字再决定），稳态零响应式写入；`cardStyle` / `listStyle` 保持 `computed`，只依赖这些 ref；禁止每帧 `querySelectorAll`（zones 每 8 帧）；禁止在 rAF 里改 `nodes` / `edges`。

## 十、校验与验收要点

**门控三条**（脚本最后统一跑，本文未跑）：`npm run typecheck`、`npm test`、`npm run build`。预期风险点：`@vue-flow` 新增 prop 名拼写、`PracticePrepare` 联合收窄后的穷尽分支（TS 会在 `switch` 漏分支处报错，正好当检查）、`guide-anim` 的 `GuideRect` 类型复用、`i18n-coverage.test.ts` 对新改文案的兜底（改文案不补译会在这里红）。

**人肉浏览器验收**（由主代理做，逐条可判）：

1. **动效是否顺**：进跟练 / 切步 / 出成片卡时相机是滑过去的（不是瞬移）；聚光框跟节点；拖动或缩放画布时聚光**跟手不滞后**（对比现状的 400ms 一跳）；收起/展开卡片、清单折叠是过渡不是硬切；切步时卡片内容淡入且**没有高度跳变**。
2. **只读是否生效**：跟练中拖节点 / 连线 / Delete / ⌘V / **⌘V 的原生粘贴（复制一个节点信封、进跟练前复制、再在画布上按 ⌘V）** / ⌘Z / 右键菜单 / **节点内双击进编辑态（文本节点是教具）** / 上传 / 从资产库落图 / 工作流落图 / 一稿多版 / 对话栏 / **选中浮动条（先选中一个已有产物的图片节点，确认浮动条不出现；若出现，点「反推提示词 / 高清 / 角色三视图」必须无效）** 全部无效且有一句提示；**生成按钮可用且只演回放**（任务中心与余额不变，可截图对比）；平移缩放仍然可用。
3. **聚光是否跟手 + 卡片是否盖住画布**：卡片不压锚点、不压清单（硬禁区）、不压常驻面板；**Inspector 全程是紧凑态**（不再展开成大面板盖住画布），且提示词框**键不进字**（contenteditable）、模型 / 参数是灰的。
4. **每条剧本走通**：7 条各走一遍，重点看多产物步（分镜 2+2、扇出 3、一景两镜 2）的 byKey 回放各自落在正确节点上；失败演练各出现一次且重试成功；**`talking-and-audio` 额外验两条支路**：清单里有带 `native_audio` 的模型时走口播（生成按钮可点、`inspector-talking` 有锚点），没有时退回首帧驱动 + notice，且「跳过这一步」都能把进度推下去（主按钮不卡死）。
5. **退出还原**：退出后节点数 / 连线数 / 视口 / 画布名 / 保存机回到进跟练那一刻；撤销栈停在进跟练前（⌘Z 一次不会回到跟练中间态）。
6. **零消耗证据**：全程任务中心与余额无变化；`voice.mp3` 能出声（音频节点回放）。
7. **跨画布**：跟练中离开画布页再进另一张画布，会话不应残留（`onScopeDispose` 那条）。
8. **reduced-motion**：系统开启「减少动态效果」后，相机与聚光直落、过渡近似瞬时。

## 十一、风险与不做

**不做（明确列出理由）**：

1. **不动后端 `easytv-api`**：`subjectIds/subject_versions`、口播 `preset/audio`、音频 `lang/voice` 都走既有契约；卡片上不再承诺「真跑」（真跑已删）。
2. **不改 `CanvasChat`**：跟练期间直接不渲染对话栏（`index.vue` 一处 `v-if`），代价是进出跟练各一次 240ms 宽度过渡 + 用户草稿态丢失（CanvasChat 未导出草稿持久化，未验证）。备选方案（给 CanvasChat 加 `readonly` prop）留待产品确认。
3. **不改三步新手引导 `CanvasGuideTour`**：两套浮层继续互斥（`canvasGuideOpen=false`）。
4. **不真跑、不新增 npm 依赖、不新增接口**。
5. **不做 3D 预演 / Blender / Codex 课程**（§二 理由）；不做媒体动作 / 蒙太奇 / 一稿多版 / 合成的回放演示（要真 `assetId`）。
6. **不做多产物 showcase**：一条剧本只有一张成片卡（`PracticeShowcase` 单 url）；多产物在各自节点上预览。
7. **不做卡片高度动画**、不做 `spot` 的 CSS transition（§6.2/6.3 理由）。

**仍有风险的点**：

1. **口播回放无声**：仓库示例视频无音轨（笔记 02 §五 ffprobe 实测），`voice.mp3` 只能证明音频节点出声；如果产品要求「口播必须听到声」，需要 W5 额外生成一条带音轨的示例视频（本轮未点名，属可选）。
2. **主体库为空**的路径只能靠 `session.notice` 兜住，观感弱于引用了真主体的路径；真实主体引用在提交侧的行为（参考图入 inputs + look 追加提示词）本方案**不触发**（零消耗），所以那条链路只有仓库级证据。
3. **`CanvasInspector` 的 `readonly` prop** 是本方案对最大组件的一次侵入式改动：禁用面较多（chips / 模型 / 规格 / 主体 / 展开），漏一处就出现「跟练中还能改参数」，只能靠 §八 的源码断言 + 人肉验收兜。
4. **性能未实测**：每帧 1 次 `querySelector` + rect、每 8 帧 10 次 `querySelectorAll` 的真实耗时未在浏览器量过（笔记 03 标注未实测）；若 `measure` 单帧 > 0.3ms，需把 zones 降到每 16 帧。
5. **`transform` 迁移的历史包袱**：`readCardSize` 依赖 inline `width`（`CanvasPracticeTour.vue:201`），迁 transform 时必须继续写；这条没有测试接着，是本轮最容易静默失效的一处。
6. **i18n 规模**：≈190 键 × 6 语言，漏一条即覆盖断言红；建议 W6 在 W1 冻结剧本文案后一次性批量补，避免边写边翻。
7. **跨页会话**：`useState('canvas-practice')` 是跨页共享的，本方案用 `onScopeDispose` 复位兜住；未验证「带 active 会话直接路由到另一张画布」的真实表现。
8. **`prepare` 从「找不到就 fail」变成「找不到就建」**（`useCanvasPracticeHost.ts:366-370` 的行为反转）：好处是六条剧本能跑通，风险是**误建节点**（例如某个 prepare 因判据快照过期被重复入列）。兜底：`key` 定位 + `gateSatisfied` 判重（原 `add-node`/`add-connect` 分支的判重逻辑保留）+ 退出整张还原，误建最多在会话内多一个节点、退出即消失。
9. **口播课的平台前提**：`resolveTalkingModel()` 依赖模型清单里存在带 `native_audio` 的视频模型；清单由运营配置（`canvas-workflow-presets.ts:9、264-265`），本方案只做「有则用、无则退回首帧驱动 + notice + 可跳过」，**不承诺**一定演出口播出声（而且示例视频无音轨，听不到也不代表实现错）。
