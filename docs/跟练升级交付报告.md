**这次做了什么**：把「新手跟练」从 4 条同骨架剧本、只能写「提示词 / 模型 / 参数 / 连线」的引导，升级为一套 7 条从易到难的课程 + 全程只读沙盒 + 有质感的镜头与浮层动效，并补齐 6 个语言包。

## 二、正面回答负责人的疑问

### 1）为什么原来的四个剧本都是图生视频？为什么没有分镜 / 角色 / 场景 / 音效引导？

不是平台没实现，是三层原因叠出来的（结论出处：笔记 02 §一，原文给了逐条证据）：

1. **剧本层刻意共用一副骨架**：上一版 `canvas-practice.ts:580-587` 的注释自己写明「四条共用同一副骨架（八步……），差别只在场景文案、平台规格与提示词——这样判据、兜底、自动备好、成片卡四套机制一套吃四条剧本」。这是编排选择。
2. **跟练引擎的写入面太窄**：旧 `PracticePrepare` 只有 5 种（prompt / model / add-node / add-connect / connect），没有任何一种能写 `subjectIds`、`data.talking`、文本节点正文、音频参数；旧回放也只认 image / video（笔记 02 §一第 2 条，引 `useCanvasPractice.ts:149`、`canvas-practice.ts:47-55`）。
3. **少数能力平台确实没有**（音效生成、单节点多分镜），所以旧版连「假演示」都做不了（笔记 02 §六）。

本次把第 2 层补齐：6 种 prepare + 8 种判据 + audio 回放，于是「角色 / 场景 / 分镜 / 口播」都能用回放式课程表达；第 3 层的缺口写进课程正文与 §七。

### 2）是平台还没实现这些能力吗？（逐项）

**平台已有（本次已用或可做课）**——按笔记 02 §三 / §六逐条：

| 能力 | 平台现状 | 证据 |
| --- | --- | --- |
| 角色 / 场景 / 道具主体库 | 有（kind = character / scene / prop） | `app/types/creative.ts:1534`（笔记 02 引） |
| 节点引用主体（版本锁定） | 有；提交时服务端把参考图并入 inputs 并把 look 追加进提示词 | `app/utils/canvas-node-kinds.ts:69-71`；`CanvasSubjectPicker.vue:9-11` |
| 多镜头分镜结构 | 有（`multi-shot` 预设「一脚本多链，互不串提示词」） | `app/utils/canvas-workflow-presets.ts:184-203` |
| 分镜组 / 编剧节点 / 剧本 API | 有（分镜组唯一入口「分镜组拼接」要真 assetId；编剧节点是演示壳） | `app/utils/canvas-group.ts:13-24`、`app/api/screenplay.ts`（笔记 02 §三③） |
| 口播 talking | 有（videoMode=talking + data.talking；台词自动算时长；模型要带 native_audio） | `app/utils/canvas-talking.ts:11-23,67-84` |
| 音频节点 / TaskType audio | 有（时长 / 语种 / 音色；节点可播） | `canvas-node-kinds.ts:9,472`、`app/types/creative.ts:159` |
| 媒体动作（高清 / 补帧 / 拉片 / 分离音频…） | 有（但都要真实 assetId / taskId） | `app/utils/canvas-media-job.ts:43-60` |
| 一稿多版、合成、蒙太奇 | 有（入口在成片工作室 / 要求真产物） | `app/utils/canvas-matrix.ts:144-152`（笔记 02 §三⑤） |
| 3D 导演台 + GLB 导入 | 有（机位关键帧求值、截图、运镜视频导出） | `docs/3D场景预演与新管线调研.md` §三 |

**平台确实没有（写进课程正文，不用假演示糊）**——按笔记 02 §六逐项：

1. **单节点 multi_prompt**（一条视频吃多条分镜提示词）：前后端契约都是单值 prompt，全仓零命中。
2. **BGM / 音效生成**：只有「自备音频资产」与「从视频分离 / 提取」，没有文生音乐或音效库。
3. **独立形态的「分镜 / 角色 / 场景节点」**：角色 / 场景是主体库的两种 kind，不是节点形态。
4. **画布内的合成 compose 与一稿多版派生**：要真实画布、真实产物，零消耗沙盒表达不了。
5. **音频语种 / 音色持久化**：Inspector 本地 ref、不落节点 data（所以本课只写时长）。
6. **全景图 / 音频 / 文本任务的回放通道与素材**：旧引擎没有（本次扩了 audio 回放并新增 `voice.mp3`；全景仍无 2:1 素材）。

一句话：**平台不缺底层节点与资产，缺的是把它们编成课程的内容设计与接线**；音效生成与单节点多分镜是真缺口。

### 3）现在覆盖了哪些创作方向？哪些没覆盖、为什么？

**已覆盖（7 条课逐条）**：见 §一课程表。方向口径：入门骨架 / 角色一致性 / 场景延续 / 多镜头分镜 / 口播与音频 / 多规格交付 / 镜头语言。

**未覆盖**：

| 方向 | 原因 |
| --- | --- |
| 3D 预演 → 出片（含 Blender / Codex） | 缺「按时间轴精确导出帧序列」「白模 / 深度 pass」两块基建；本轮不做（3D 调研 §一、§七） |
| 音效 / BGM 生成 | 平台没有生成能力（缺能力） |
| 单节点多分镜（multi_prompt） | 平台没有（缺能力） |
| 合成 / 一稿多版 / 蒙太奇 / 媒体动作演示 | 要求真实 assetId，回放产物 assetId 恒为 undefined（这次不做，设计 §二末条） |
| 全景图课 | 无 2:1 素材、本轮未扩 panorama 回放（这次不做） |
| 策划案建画布 → 分镜 | 会新建一张画布，跟练沙盒表达不了（这次不做） |

### 4）「codex 类智能体 + Blender 生成场景 → Seedance 出片」在平台上能做成什么样？

按 `docs/3D场景预演与新管线调研.md`：

- **结论（§一）**：第一版不做 Blender / Codex，也不做「文本 → 整场 3D 场景」；**第一版做「导演台运镜 → 导出预演帧序列 → 图生视频」**——全部踩在仓库已有能力上，1–2 周可交付。
- **为什么（§七）**：外部实测「整场场景」成功率 0%（外部调研来源、未在仓库复核），单资产生成可用但整场仍是 demo 级；仓库是纯前端 + 已冻结的 easytv-api，没有跑 Blender 进程的位置；导入侧只吃 GLB/GLTF，即使 Blender 出图也要回到「截图 / 帧序列 → 上传 → 落节点」这条同一接缝。**先把接缝（阶段一）做对，外部 3D 生成才有插进来的口子。**
- **推荐首步（§五阶段一 + §六第一名流程）**：新增纯前端「预演导出器」`app/utils/director/export/preview-frames.ts`（不动 `video-export.ts`）：`planPreviewFrames(camera, sampling, shots)` 纯规划 + `exportPreviewFrames({project, cameraId, output, sampling, renderAt, upload})` 执行；复用 `evaluateCameraPath`（`app/utils/director/camera-path.ts:133`）与已开的 preserveDrawingBuffer 截图口径；每镜自动建 video 节点（首帧 i2v、首尾帧 fl2v）+ 运镜 prompt（复用 CAMERA_MOVE_ITEMS / expandCameraTokens）；批量提交 + 点数预估。首版只做彩色输出、每镜首尾帧（≤ 6 帧）。
- **与跟练的关系（3D 调研 §九）**：这条链路落地后最适合做「下一条高阶跟练剧本」——形态是「预演帧序列 → 每镜一条 image→video」，引擎不用换；但要先补预演片素材，并把 `PracticeReplay` 单 url 结构扩成多产物（属另一件事）。
- 更靠后的阶段二 / 三：深度 / 白模控制通道抽象（需服务端透传，与 easytv-api 另行排期）、文本 / 图片 → 3D 生成接入导演台（需外部 3D 生成 API）。
