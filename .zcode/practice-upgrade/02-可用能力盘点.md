# 02 · 可用能力盘点：分镜 / 角色 / 场景 / 音效，平台到底有没有

> 针对产品负责人第 1 条疑问：「现在四个跟练剧本全是图生视频同一副骨架……oiioii 的跟练里有分镜、角色、场景、音效等节点的引导。是平台还没实现这些能力吗？」
> 只读盘点，全部结论以本仓库（easytv-web）代码为准；后端 `easytv-api/API.md` 仅在需要确认「平台有没有」时只读引用（标注「后端文档」）。日期 2026-10-10。

---

## 一、一句话结论

**不是「平台没实现」。** 角色 / 场景 / 分镜 / 口播四类都有真实可用的平台能力（主体库、主体引用、多镜头预设、策划案建画布、口播 talking、音频节点、媒体动作），四个剧本长成同一副骨架的真实原因是另外三条：

1. **剧本层刻意共用一副骨架**：`app/utils/canvas-practice.ts:580-587` 的注释写明「四条共用同一副骨架（八步……），差别只在场景文案、平台规格与提示词——这样判据、兜底、自动备好、成片卡四套机制一套吃四条剧本」。这是设计选择，不是能力缺失。
2. **跟练引擎只会写「提示词 / 模型 / 参数 / 连线」**——它没有任何写入 `subjectIds`、`talking`、文本节点正文、分镜组、音频参数的 prepare 种类，也没有 image/video 之外的 replay 种类（`app/utils/canvas-practice.ts:47-55` PracticePrepare 五种；`app/composables/useCanvasPractice.ts:149` 回放只认 image/video）。
3. **少数能力平台确实没有**：单节点 multi_prompt 多分镜、BGM/音效生成、独立形态的「分镜 / 角色 / 场景节点」（角色设计师节点是对话入口的演示壳）；另有一批能力（合成 compose、一稿多版、蒙太奇、媒体动作）**存在但进不了零消耗沙盒**——它们要么要求真实 `assetId`，要么入口在成片工作室而不在画布。

对负责人的直接回答可以概括为：**能力大多在，缺的是「把它们编进跟练」的接线，以及把「角色/场景/分镜/口播」从手工链路改造成回放式演示所需的几类新写入种类；音效生成与单节点多分镜是真缺口。**

---

## 二、判定口径（本文三档的含义）

- **可做跟练**：现有回放机制 + 现有 UI 就能整条演示（自动布节点 / 写参数 / 连线 / 回放产物，不需要用户动手、不需要平台没有的 UI）。
- **需小改**：平台能力存在，但跟练要「新增 prepare / replay 种类」或补一个很小的接线/素材，才能做成回放式课程。
- **不可做**：平台没有该能力，或该链路必须真实产物 / 真实扣点 / 入口在体系外，回放式引导表达不了。

---

## 三、五条候选方向逐条盘点

### ① 角色一致性 —— 需小改（平台能力：有）

**链路「选角色 → 出图 → 出片」现在能不能在画布里走通？能（手工），且三段都是真实链路：**

| 环节 | 在哪 | 依据 |
| --- | --- | --- |
| 主体库（kind = character / scene / prop） | `app/types/creative.ts:1534`；增删改查 / 三视图生成 / 版本 | `app/api/subject.ts:5-43`、`app/pages/subjects/index.vue:221` |
| 节点引用主体 | 图片 / 视频节点 Inspector 的「主体」按钮 → 选最多 4 个 | `app/components/canvas/CanvasInspector.vue:403`（`canUseSubjects = image|video`）、`:404`、`:937-944`、`app/components/canvas/CanvasSubjectPicker.vue:31-46` |
| 存到节点 | `data.subjectIds` + `data.subjectVersions`（版本锁定） | `app/utils/canvas-node-kinds.ts:68-71`、`CanvasInspector.vue:437-451`（`lockedVersions`） |
| 提交 | 请求带 `subject_ids` / `subject_versions`；**服务端把主体参考图并入 inputs 并把 look 追加到提示词** | `app/api/task.ts:29-33`、`app/composables/useCanvasGenerate.ts:161-162, 271, 288`、`app/components/canvas/CanvasSubjectPicker.vue:9-11` 注释；后端文档 `easytv-api/API.md:956, 966` |
| 节点上显示 | 主体 chip 行（无封面时回落「主体 #id」+ 图标） | `CanvasInspector.vue:1060-1076` |

**跟练为什么做不了这一段（需要的小改）：**
- 现有 prepare 不能写 `subjectIds / subjectVersions`（`canvas-practice.ts:47-55` 只有 prompt / model / connect / add-node / add-connect；宿主也只按这五种执行 `useCanvasPracticeHost.ts:281-391`）。
- 「选角色」这一步的平台 UI 是一个弹窗（CanvasSubjectPicker，Teleport 到 body），跟练没有打开弹窗的机制；正确做法不是开弹窗，而是**新增写 subjectIds 的 prepare 种类**，直接把「已引用主体」状态放进画布。
- 用户主体库为空时，chip 只能显示「主体 #id」占位（`:1062-1065`），课程文案要兜住这一点；「生成三视图」会真实建 3 个图片任务（`app/api/subject.ts:23-27`），**不能进零消耗跟练**，课程应从「选一个已有主体」起步。

**注意**：**角色设计师节点不能当这条课的起点**——它只能从对话工具栏落节点（`app/utils/canvas-node-kinds.ts:476` hidden、`app/components/canvas/CanvasChat.vue:64`、`app/pages/canvas/index.vue:761`），面板里 6 个角色是写死的演示数据（`app/components/canvas/CanvasCharacterDesignerNode.vue:25`, `app/utils/canvas-demo-cast.ts:1-6`「后端接口就绪前先用这份数据渲染」），「重试 / 取消 / 删除」只是本地状态与 toast（`:71-83`），**唯一真链路是「加到资产库」→ `subjectApi.create({ kind:'character' })`**（`:59-69`）。

### ② 场景一致性 —— 需小改（平台能力：有）

**「场景定调 → 出图 → 出片」有三条真实走法：**

1. **主体库 kind=scene**：与角色同一套选择器与提交链（`CanvasSubjectPicker.vue:34, 39-41`），节点上同样写 `subjectIds` → 服务端带参考图 + look。
2. **场景参考图（set 角色）**：视频/图片节点可挂 `setAssetId/setUrl`，提交时按 `role: 'scene'` 进 inputs（`app/utils/canvas-refs.ts:13`、`app/utils/canvas-task-inputs.ts:83-84`；入口 `CanvasWorkspace.vue:3713-3722`「选择场景」资产选择器；Inspector thumb 标签 `CanvasInspector.vue:103`）。
3. **全景图节点**：菜单里真实存在（`canvas-node-kinds.ts:474`），走图片任务、尺寸锁 2048×1024（`:623-631`、`useCanvasGenerate.ts:199, 271-277`），双击有球面预览（`CanvasWorkspace.vue:179, 5003`）。

**跟练为什么做不了（需要的小改）：**
- 写 `subjectIds` 同上；写 `setAssetId` 也是新的 prepare 种类（还要一个真实资产 id，或接受只有 url 的降级参考——提交时没 assetId 会提醒「不在资产库」）。
- **全景图回放没有素材**：`replaySubmit` 只拦 `kind === 'image' | 'video'`（`useCanvasPractice.ts:149`），全景（panorama）节点点生成会走真实提交；且仓库没有 2:1 的示例素材（`public/images/tutorial` 只有 frame.jpg + clip.mp4，详见第五节）。
- 没有独立的「场景节点」形态；「镜头」在 Inspector 里是摄影镜头（lens）配置（`CanvasInspector.vue:82-104, 300`），不是分镜镜头。

### ③ 多镜头分镜 —— 需小改（结构可演示；multi_prompt 没有）

**四条候选路径，最适合做「分镜」引导的是「多镜头分镜」预设：**

| 路径 | 是否 canvas 原生 | 结论 |
| --- | --- | --- |
| `multi-shot` 预设：一个文本脚本 → 2 张首帧 → 2 条独立 image→video 链 | 是，纯节点结构 | **最适合**：`app/utils/canvas-workflow-presets.ts:184-203`（teachingPoint 明确「一脚本多链，互不串提示词」） |
| 编剧 / 策划案（screenplay）→ 分镜：一句话生成策划案 → 按镜建画布（角色图 / 分镜图 / 视频 / 配音四层 `sp.layer`） | **否**，在「一句话成片」向导里，且会新建一张画布 | 平台有（`app/api/screenplay.ts:8-48`、`app/pages/create/index.vue:37-43`、`app/components/create/CreateLayers.vue:121-125`、`app/utils/create-layer-nodes.ts:5-6`；后端文档 `easytv-api/API.md:830`）。跟练沙盒里表达不了 |
| 分镜组 `group(storyboard)`：把一串图片按 cols 排成网格、带「分镜组」角标 | 是 | 结构存在（`app/utils/canvas-group.ts:13-24`、`CanvasGroupNode.vue:106`），但**唯一入口是「分镜组拼接」**（`useCanvasImageEdits.ts:1430-1478`），而拼接要求真实 assetId（`canvas-montage.ts:1-5, 76-80`），回放产物没有 |
| 蒙太奇拼接（ffmpeg 拼宫格大图） | 是（媒体作业） | 需要 `asset_id`（同上），回放产物 `assetId=undefined`（`canvas-practice.ts:379-380`），**演示不了** |
| 逐帧拉片 `storyboard` 媒体动作 | 是（媒体作业） | 同样要求 asset/task（`canvas-media-job.ts:4-13`），且属「拉片」不是「分镜编排」 |

**「一条视频节点吃多条分镜提示词（multi_prompt）平台到底有没有？——没有。**
- 全前端 grep `multi_prompt` / `multi-prompt` / 多段提示词数组：**零命中**（只有预设 id `multi-shot`）。
- 后端同样零命中（只读检索 `easytv-api` 的 `*.md` `*.go`）；`POST /user/task` 的请求体是单值 `prompt`（后端文档 `easytv-api/API.md:290`），策划案的多镜是**每镜一个任务**（`API.md:821`，`shots[].prompt` 每镜一条）。
- 平台上的「多镜头」= 多个 video 节点 + 合成/拼接，**不是**单节点多 prompt。

**跟练要动的小改**：现有 `add-node` / `add-connect` 都按「作用域里第一个同类节点」找工作（`useCanvasPracticeHost.ts:264-268, 284`），只能搭出 **一条** image→video；多镜头要多条链，需要「按身份/编号建节点并连线」或直接落一段子图（见第四节）。

### ④ 口播与音效 —— 口播：需小改；音效/BGM：不可做

**平台能力盘点：**
- 音频节点真实存在（kind=audio，`canvas-node-kinds.ts:9, 472`；TaskType audio `types/creative.ts:159`），Inspector 有 时长 5/10/15/30s、语种（`useLangs`）、音色 三个参数（`CanvasInspector.vue:127, 396, 471-472, 518-527, 1346-1374`），提交时 `duration` 进 params、`lang/voice` 进请求顶层（`:654, 671-676`；`app/api/task.ts:34-37`「按语种先翻译台词再 TTS」）。节点用 `<audio>` 播放（`app/components/canvas/CanvasAudioPlayer.vue:149-155`）。
- 口播 talking 预设：视频节点 `videoMode='talking'` + `data.talking{script,tone,framing,duration}`，台词拼提示词、时长按台词自动算（3.5 字/秒 + 1 秒收尾，3–15s），模型要带 `native_audio` 能力位（`app/utils/canvas-talking.ts:11-23, 67-84, 95-105, 107-119`；Inspector `:645-652`）。
- 媒体动作（工具条）：高清/补帧（`hdParams` 含 interp、slowmo）、片段重拍、逐帧拉片、片段截取、深度动作、去字幕、**音视频分离 `/ 人声分离 / 背景音提取`**、语音转字幕、去静音、智能抠像、主体消除等（`app/utils/canvas-media-job.ts:43-60`、`canvas-node-kinds.ts:180-241`、`app/utils/canvas-sel-actions.ts:52-95`）。
- 字幕翻译：`subtitleApi.translate` 真接口（`app/api/screenplay.ts:53-56`），画布里目前用于一稿多版的多语言派生（`CanvasMatrixPanel.vue:205-231`）；策划案整份台词翻译 `localize`（`screenplay.ts:42-45`）；成片时间线的字幕来源支持画布上的 SRT 文本节点（`types/creative.ts:1338-1339`、`CreateTimeline.vue:36-37, 100, 550-552`）。
- **BGM / 音效：没有生成能力。** 平台只有两条路：① 成片时间线挑**你自己的音频资产**当 BGM（`CreateTimeline.vue:35, 105-107, 556-558, 712-725`；`types/creative.ts:1332-1334`）；② 从视频里**提取**（`bgm_separation`，后端文档 `easytv-api/API.md:1722`）。没有文生音乐 / 音效库 / SFX 面板（前端 grep `bgm` 只命中上面这些；无 music/sfx 生成接口）。

**跟练要动的小改（口播）**：
- 新增写 `data.talking` 的 prepare 种类（当前 prepare.model 只能写 `videoMode`，写不了 talking 对象，`useCanvasPracticeHost.ts:379-388`）。
- 口播回放本身没问题：第 7 步仍是 video 回放（`canvas-practice.ts:678`）。
- 音频参数有个隐藏坑：**`audioLang/audioVoice` 只是 Inspector 的本地 ref，不落节点 data**（`CanvasInspector.vue:471-472` 初始化、`:672-675` 提交时读），所以「写音频参数（语种/音色）」需要平台小改（让它们可持久化），否则跟练只能写 `duration`。

**音效为什么不可做**：没有生成源；而「分离音频 / 提取 BGM」等媒体动作必须挂在真实 `assetId/taskId` 上（`canvas-media-job.ts:4-13, 80-85`），回放产物两个 id 都是 undefined（`canvas-practice.ts:379-380`），连触发的资格都没有。

### ⑤ 合成与交付 —— 不可做（跟练回放式；能力本体在成片工作室）

- **合成 compose**：真接口 `POST /user/canvas/:id/compose`（`app/api/screenplay.ts:57-67`），入口在「一句话成片」向导第 4 步（`app/pages/create/index.vue:507-540`），按时间线只合启用镜头（≤24，后端文档 `API.md:1192`），可出 480p 预览与交付包（package）。画布内没有 compose 按钮（画布内相近的是 ffmpeg 蒙太奇拼图）。
- **一稿多版矩阵**：面板存在（`CanvasWorkspace.vue:191, 4692`），但**门槛是真实产物**：`matrixEligibility` 要求 `assetId > 0` 且 content 非空（`app/utils/canvas-matrix.ts:144-152`）——回放产物没有 assetId，派生面板会直接拒绝。
- **导出 / 下载**：都是真实操作不是演示——画布文件导出/导入（`app/pages/canvas/index.vue:604-629`）、单节点媒体下载（`CanvasWorkspace.vue:2652-2666`）、分享只读链接（`pages/canvas/index.vue:699-709, 1006`）。
- **成片卡**：这是跟练自身已有的展示机制（`canvas-practice.ts:73-79`、宿主 `ensurePracticeShowcase` `useCanvasPracticeHost.ts:422-455`），**不是平台能力**，新课程可以继续用。

**结论**：⑤ 作为「跟练课程方向」不可做——不是平台缺能力，而是这条链必须在真实画布、真实产物上跑，且入口不在画布；零消耗回放表达不了。若只教「观念」，可以放在课程文案里（例如「一稿多版要真出片后才能派生」），但不能做成回放步骤。

## 四、回放式演示可行性 + 需要新增的 prepare / replay 种类

### 4.1 哪些方向能用回放式演示表达

**用今天的跟练机制（prepare 五种 + replay image/video），五个方向里没有一个能超出「图片 → 视频」骨架。** 差别只在新增多少种类：

| 方向 | 回放式可行性 | 说明 |
| --- | --- | --- |
| ① 角色一致性（选主体 → 出图 → 出片） | **可（需 1 种新 prepare）** | 写 subjectIds 即可；主体 chip 有占位降级 |
| ② 场景一致性（主体 scene / 场景参考） | **可（需 1-2 种新 prepare）** | 写 subjectIds / setAssetId；全景图另需 replay 扩容 + 素材 |
| ③ 多镜头分镜（multi-shot 结构） | **部分可（需身份化布点 + 连线）** | 分镜组 / 蒙太奇 / 策划案不可 |
| ④ 口播 | **可（需 1 种新 prepare；音频产物另议）** | talking 数据写进去，视频回放已有 |
| ④ 音效 / BGM | **不可** | 无生成能力；媒体动作要真资产 |
| ⑤ 合成 / 一稿多版 / 导出 | **不可** | 要真画布真产物，入口在成片工作室 |

### 4.2 需要新增的 prepare 种类（逐条：种类名 → 数据结构 → 由谁写入）

> 现状：`PracticePrepare` 联合定义在 `app/utils/canvas-practice.ts:47-55`；执行在宿主 `useCanvasPracticeHost.practicePrepareAction`（`useCanvasPracticeHost.ts:281-391`）。**类型与计划由「剧本层」定义，真正写画布由「宿主层」执行**——新种类沿用这条分工。

| 种类名 | 数据结构（建议） | 由谁写入 | 说明 |
| --- | --- | --- | --- |
| `subject` | `{ kind:'subject', nodeKind:'image'\|'video', ids:number[], versions?:Record<string,number> }` | 剧本层定义类型；**宿主层**写 `updateNodeData(id, { subjectIds, subjectVersions })` | 覆盖 roles 与 scenes 两个方向；versions 缺省按主体当前 version 锁 |
| `talking` | `{ kind:'talking', nodeKind:'video', script:string, tone?, framing?, duration? }` | 剧本层定义；**宿主层**写 `data.talking`（并同步 `videoMode:'talking'`） | 默认值走 `normalizeTalkingData`（`canvas-talking.ts:42-55`） |
| `text` | `{ kind:'text', nodeKind:'text', content:string }` | 剧本层定义；**宿主层**写 `data.content` | 注意：文本节点的正文是 `content` 不是 `prompt`（`CanvasNode.vue:654,665`），现有 `prompt` 种类写文本节点不会显示 |
| `audio-params` | `{ kind:'audio-params', nodeKind:'audio', model?:string, params:{ duration:number }, lang?:string, voice?:string }` | 剧本层定义；**宿主层**写 model/params；lang/voice 需要平台先让它们能落节点（见 ④ 的坑） | 目前只有 `duration` 可写 |
| `connect-by-key` / 身份化 `add-node` | `{ kind:'add-node', nodeKind, key:string, label?, prompt? }` + `{ kind:'connect', fromKey:string, toKey:string }` | 剧本层定义；**宿主层**解析 key→节点 id 后建点/连线（替换现在「第一个同类节点」的 `practiceScopeNode`） | 多镜头（③）必需；单链课程不受影响 |
| `group-storyboard` | `{ kind:'group-storyboard', keys?:string[], cols?:number, label? }` | 剧本层定义；**宿主层**建 group 节点并挂 `parentNode`（参考 `useCanvasImageEdits.ts:1443-1478` 的建组参数） | 只做「分镜组」排版，**不触发蒙太奇**（那要真资产） |
| `replay` 节点类型扩容 | 现有 `PracticeReplay` 增加 `type?: 'image'\|'video'\|'audio'\|'text'`（或直接按节点 kind 白名单放宽） | 剧本层声明；**会话层** `useCanvasPractice.replaySubmit` 执行（`useCanvasPractice.ts:143-188`） | 现状只拦 image/video（`:149`）；audio 节点、panorama、文本任务都需要它 |
| 文本回放（可选） | `{ simulatedMs, text:string }`（复用 `canvasTaskPatch` 的 `type==='text'` 分支写 content，`canvas-task-apply.ts:12-13`） | 剧本层 + 会话层 | 「编剧写脚本」类步骤的零消耗回放，不需要素材文件 |

> 新增 prepare 种类还要同步三处消费点，别漏：`practiceReadyItems`（`canvas-practice.ts:347-364`）、Tour 的 `readyText`（`CanvasPracticeTour.vue:108-116`）、以及自动备好的入列规则（`practiceAutoPreparePlan`，`:308-329` 本身不用改，它按 prepare 原样入列）。

## 五、回放素材：音频节点回放用什么？

**核对结果（本次实测）：仓库里没有任何音频素材，clip.mp4 也没有音轨。**

- `public/images/tutorial/` 只有 `frame.jpg` 与 `clip.mp4`（ls）。
- `ffprobe` 实测（本机 ffmpeg 8.0.1，本次运行）：
  - `clip.mp4` → 只有 1 条流：`codec_type=video, codec_name=h264, duration≈5.04s`，**无音频流**。
  - `public/videos/camera-movement/fixed.mp4` → 同样只有 h264 视频流，无音频。
  - `frame.jpg` → 1280×720。
- `find public server app/assets -iname "*.mp3|*.wav|*.m4a|*.aac|*.ogg|*.flac"` → **零命中**。

**结论：**
1. **`clip.mp4` 的音轨不能当音频产物**——它根本没有音轨；用 `<audio src="clip.mp4">` 只会静音（浏览器能解 mp4 容器，但解不出不存在的声音）。
2. **必须新增一个音频文件**（除非课程把「口播」也做成纯视频回放、不产出音频节点）。做法：
   - **放哪**：`public/images/tutorial/` 下（跟回放素材同目录，例如 `voice.mp3`）。注意 `isMediaUrl` 只认 `/upload/`、`/videos/`、`/images/` 前缀或 http(s)/data/blob（`app/utils/media.ts:21-24`），所以**不能**新建 `public/audio/` 这类前缀放（节点会判成非媒体地址不渲染）。
   - **由谁在哪个阶段生成**：按本次约束「要新增素材必须在实施清单里点名由谁在哪一步生成」——设计文档的实施清单里点名，建议由 **W5（样式与动效/素材）在实现阶段** 产出：优先用一条 5–10 秒旁白 TTS（离线工具，或主代理在有额度的账号上用平台自己的音频模型跑一次，只做一次素材、不进跟练运行时）；退一步可用 ffmpeg 生成一段占位提示音（能出声、但课程演示会显得假，不推荐）。产出的文件随代码提交，不需要新增依赖。
   - **为什么现在没有**：四个现有剧本全是图片→视频，从未需要音频产物；仓库历史上也没有任何音频示例（下面的 find 证据），不是被误删。
3. 音频节点回放还差一步接线：`replaySubmit` 目前只拦 image/video（`useCanvasPractice.ts:149`），需要按 4.2 的 replay 扩容，产物补丁可复用 `practiceReplayPatch`（`canvas-practice.ts:373-384`，会写 content=url、taskId/assetId 清空）。
4. 全景图（②）同理：没有 2:1 素材；要么新增一张，要么把全景路线从课程里去掉。

## 六、平台确实还没有的能力（写进交付报告，直接回答负责人）

1. **单节点 multi_prompt（一条视频节点吃多条分镜提示词）**：没有。前端与后端契约都只有单值 prompt；多镜头靠多节点 + 合成/拼接。
2. **BGM 生成 / 音效（SFX）生成或音效库**：没有。只有「用户自备音频资产」与「从视频分离/提取音频」。
3. **独立形态的「分镜节点 / 角色节点 / 场景节点」**：没有。角色 / 场景是「主体库引用」的两种 kind，不是画布节点形态；「角色设计师」「编剧」是对话工具栏落下的演示壳节点（角色设计师只有「加到资产库」是真的；编剧节点是静态 DEMO_SCRIPT，只能复制大纲）。
4. **画布内的合成 compose**：没有（合成在成片工作室；画布内是 ffmpeg 蒙太奇拼图）。一稿多版同理要求真实产物。
5. **全景图 / 音频 / 文本任务的回放通道**：跟练引擎没有（只有 image/video 回放）；也没有对应示例素材。
6. **音频参数（语种 / 音色）持久化到节点**：没有（Inspector 本地 ref，不落 data），所以「口播音色/语种」目前只能现场手选、不能作为模板/跟练数据带走。
7. **（与课程设计相关）策划案建画布、媒体动作、蒙太奇、一稿多版、合成都要求真实画布/真实资产**：跟练零消耗沙盒里无法触发，不是能力缺失，而是「不可回放」。
